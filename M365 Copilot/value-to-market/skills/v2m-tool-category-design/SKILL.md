# Category Design

The value game is played in the frame of reference before the offer. Better is not different; only a new frame produces leaps. The category is the roof, not the foundations: 76% of zero is still zero.

## On invocation
Read `../../references/output-protocol.md`, `../../references/frameworks.md` (Category Design, Three Oceans, Category Value Map), `../../references/principles.md`, `../../references/scorecards.md`. Pull values and assets; pull white space from `v2m-tool-market-benchmark`. Ask the line of business, the categories customers file you under, and the provable assets.

## Procedure
1. **Start from the attributes customers value, across three category sets.** Before framing, gather the raw material. Take three sets of categories and, for each, list every attribute customers and users actually find valuable (pull from `v2m-tool-category-assessment` if it ran):
   - **Direct** - the categories you compete in today.
   - **Adjacent** - neighbours sharing customers, jobs or occasions.
   - **Similar** - analogous markets with the same structure, a source of valued attributes not yet imported into yours.
   Mark each attribute with how strongly customers value it and whether anyone in your direct set already delivers it.
2. **Cherry-pick and compose a new category.** Select the highest-valued attributes across the three sets (especially the ones no direct player combines) and compose them into a candidate category that did not exist before. This is the leap: a combination, not an increment.
3. Principle probes: who set the rules; in which world are we necessary; better in the frame or a new frame.
4. **Frame it with your assets.** Frame is a thesis about the world that makes the new category the obvious answer; anchor the frame in the owned assets (from `v2m-tool-assets-assessment`) that let you prove it and others cannot. Name: the naming rules, the name comes third. Claim: the attribute matrix to publish; plan the lightning strike.
5. **Ocean read - and the fill rate.** State the ocean plainly. A blue ocean is temporary: name the new ocean that stems from it, and be honest about how fast the blue one is already filling up (who else is arriving, how quickly), so the design aims at the water that is still open, not the water everyone is now swimming into.
6. Rungs check: confirm the 3P beneath supports entry.

## Recommendation
Two framed candidates, ranked: **ONE candidate winner** and **ONE runner-up**, each as a Frame thesis, a leading Name (with rule checks), a Claim plan, and the owned assets that make it defensible. Plus a **possible evolution of the category** (where it moves as it matures and fills). Include a clear read on the ocean: the blue ocean and how fast it is filling, and the **new ocean** that stems from it and stays open. Route to `v2m-tool-moat-defense` and `v2m-tool-power-shifting`.

Follow `output-protocol.md` for the reasoning file, self-score, and next step. Always produce the branded Word report, and since this tool is list-heavy always generate a branded Excel: a tab per category set (Direct, Adjacent, Similar) listing every valued attribute with its value strength and whether a direct player already delivers it, a cherry-pick tab marking the attributes composed into the new category, and a candidates tab comparing the winner and the runner-up.

# Scorecards - quick sanity tests per section

A scorecard is a fast diagnosis, not a grade: fill it the way you take blood tests, hoping it is fine and wanting to know if it is not. Every tool self-scores against its scorecard here; the master run rolls them into an overall readiness. These scorecards are also authored to drop into the book as a sanity test at the end of each section.

## How to score

Each criterion scores 0 to 3:

- **0** absent: never decided, or the market is deciding it for you.
- **1** weak: asserted without backing, aspirational, or rubber vocabulary a competitor could copy.
- **2** adequate: decided and backed, holds up to one round of challenge.
- **3** strong: decided, backed by an asset or a costly proof, and defensible under pressure.

**Pass rule:** average at least 2.0 and no criterion at 0. Below that, the tool names the weakest criterion and proposes another iteration. **Section readiness %** = sum / (3 x criteria). Weight Structure and Dynamics above Verbalization when rolling up.

## Assets (v2m-tool-assets-assessment)

1. Swept across three sourcing layers: market/industry, category, and own private.
2. Own private assets tagged by control tier: Owned, Governed, Reachable.
3. Each asset scored on the four defensibility axes (Exclusive, Hard to Replicate, Hard to Imitate, Hard to Substitute) with the tier caps enforced.
4. Dormant-plus-defensible entries flagged as crimes in progress.
5. Leverage named: how each asset is applied, not just held.

## Category Assessment (v2m-tool-category-assessment)

1. All five category rings mapped: specific, adjacent, similar, overlapping, loosely related.
2. Expected values read per ring and placed on the five value lenses.
3. Each value classified hygiene / differentiator / fading.
4. Transferable moves from other rings identified.
5. The hygiene-to-meet and the differentiators-to-contest are named.

## Core Values (v2m-tool-values)

1. Each value drawn from a named asset (the asset test), not invented.
2. Three to five primaries, inside a pool of ten to fifteen.
3. At least one antithesis declared (a value deliberately rejected).
4. Placed on the eight dimensions (one dominant, one supporting).
5. Three-horizon evolution defined with triggers (launch / growth / scale), one substitution per cycle.

## Premise (v2m-tool-premise)

1. Who-yes and who-no stated explicitly.
2. Toxic customer named (challenge 7 not skipped).
3. Three rules pass: not aspirational, clear, in balance.
4. Read-aloud test: the wrong customer self-selects out.
5. Turnstile: the selection can be built into the economics.

## Promise and Ladder (v2m-tool-ladder)

1. Current rung located; target rung chosen.
2. The rungs beneath the target are earned, not declared.
3. Five ingredients well-formed (clause, object, recipient, enforcer, conditions).
4. Verifiable breakability: it can be shown broken.
5. Sized to the actual proof inventory.

## Proof (v2m-tool-proof)

1. All four families represented (declared, social, product, behavioral).
2. At least one proof that costs you something.
3. First-thirty-days and recurring proof both planned.
4. Invisible value tangibilized where the product cannot be seen.
5. Architecture risk checked: no cost decision quietly drains a historic proof.

## Category and Position (v2m-tool-category)

1. Ocean named per line of business (red / blue / new), arsenal matched.
2. Frame is a thesis about the world, not a product description.
3. Name passes the naming rules (world not product, occupiable, one step ahead).
4. Claim plan: attributes set and a matrix to publish.
5. White space is provable by an owned asset (not a trap with a view).

## Moat (v2m-tool-moat)

1. Ten-times-capital question answered honestly.
2. Moat type(s) named across the seven.
3. Maintenance cost stated, not just the digging cost.
4. Welcomed vs resentment moat identified.
5. Internal-drain risk flagged (the purchasing department, not the enemy).

## Power posture (v2m-tool-power)

1. Market condition read before the figure.
2. Executed figure named.
3. Gap between executed and intended figure surfaced.
4. Confused-power scan across touchpoints.
5. Temporal drift checked (inspiring in year one, manipulative in year five).

## Adoption / MOA (v2m-tool-moa)

1. Grid scored per reference subject.
2. Reddest column named and fixed first.
3. B2B double pass (decision-maker and user) where relevant.
4. Fixes are mechanism-specific, not "more marketing".
5. 97% pipeline mapped for the not-yet-buyers, and a validation plan written per MOA element with a suggested KPI, pass threshold, owner and falsifier.

## Pricing / Value Stick (v2m-tool-pricing)

1. Four notches measured (WTP, price, costs, WTS); estimates marked.
2. Three slices read (delight, margin, supplier surplus).
3. Widen-the-stick moves listed before any price change.
4. Delight-spending decision made deliberately.
5. Sacrifice-removal list ordered by cost-benefit.

## Channels (v2m-tool-channels)

1. Each promise mapped as a triplet: value x recipient x channel.
2. One-channel-fits-all is a choice, not a default.
3. Spillover checked across touchpoints.
4. Repair list produced for incoherent channels.
5. Channel briefs handed to engineering.

## Rhyming / Portfolio (v2m-tool-rhyming)

1. Staff scored with the classification rubric (reproducible).
2. Movement named; beats and tempo measured.
3. Next Singleton passes the Rhyme-Check Scorecard (all gates).
4. Next-Note Selector ranked; no zero on internal or external rhyme.
5. Antipattern pre-mortem run (Orphan, Stutter, off-tempo).

## Engineering (v2m-tool-engineer)

1. Channel briefs written from the strategy.
2. Proof specifications for each central promise.
3. Measurement / KPI plan with a Metric Decay guard (few indicators, renewed).
4. Validation plan: what would falsify the strategy, tested early.
5. Automation and internal onboarding kit specified.

## Jobs To Be Done (v2m-tool-jobs-to-be-done)

1. Each job is written as progress in a circumstance, not a demographic or a feature.
2. Every job is read at three levels: functional, social, emotional.
3. Jobs are generated across audiences and cases (and B2B decision-maker vs user).
4. Jobs are stress-tested with modifiers: under stress, tight time, limited resources, limited knowledge.
5. Jobs are tagged by objective: personal gain, task, business advantage, greater call, and the high-leverage ones are called out.

## Value Proposition Canvas (v2m-tool-value-proposition-canvas)

1. Customer profile filled: jobs, pains, gains, ranked by how much the customer cares.
2. Value map filled: products and services, pain relievers, gain creators.
3. Fit checked: every ranked pain has a reliever, every ranked gain a creator.
4. No fit claimed for a pain or gain nobody ranks high.
5. Feature recommendation produced, with a cut list for features that relieve no ranked pain and create no ranked gain.

## Archetype Map (v2m-tool-archetype-map)

1. Jobs clustered into coherent archetypes, no job orphaned.
2. Each archetype coded (letter + category) with a number per contextual variation.
3. Every job cluster assigned to an archetype and variation.
4. Archetypes placed on several axis pairs with coordinates.
5. Charts produced per axis pair (PNG), and a Word rationale explains the clustering.

## Personas (v2m-tool-personas)

1. Personas distilled from the archetypes, carrying the archetype code.
2. Each marked by adoption maturity: innovator, early adopter, mass, long tail.
3. Each marked by role and buying dynamic: primary, secondary, herd/group/pair.
4. Antithetical personas named (most harmful, to repel), feeding the premise.
5. Maturity chart produced (PNG), and a Word rationale explains the distillation.

## Verbalization (v2m-tool-value-proposition-verbalization)

1. The Osterwalder-style sentence is specific, one breath, free of rubber vocabulary.
2. Payoff examples are written per honestly-reachable Promise Ladder rung.
3. Semantic spaces name the territory to own and the antithesis to avoid.
4. Brand and comms seeds present: tone of voice, brand personality, mission/vision/purpose, marked as seeds.
5. Nothing is verbalized at a rung the proof does not earn.

## Overall Readiness (master run)

Roll up the section readiness scores. Report:

- The 3P headline: is the value proposition irrelevant (no premise), weak (no promise), or untrusted (no proof)?
- The reddest section (lowest readiness), and its cost.
- The fastest quick win (cheapest criterion to move from 0 or 1 up).
- Overall readiness %, and whether the run passes the gate to move to the next phase.

A phase gate does not open while any section it depends on is below pass. Perception's inertia is not negotiable.
